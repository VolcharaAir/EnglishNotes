# Переход со старой версии D: на стандартное хранилище

Название файла сохранено ради ссылок из версии 0.1.0. Предыдущая инструкция
о размещении всех данных на D: отменена новым требованием переносимости.

Версия 0.2.0 хранит данные в стандартной пользовательской папке Windows:
`%LOCALAPPDATA%\EnglishNotes`. Приложение не требует наличия диска D:.
На macOS/Linux действуют стандартные пути, указанные в README.

## Автоматическая миграция

1. При запуске создаётся пользовательская папка и берётся блокировка нового приложения.
2. Если новая база уже существует (включая пустой или повреждённый файл), она имеет
   приоритет. Перезаписи, объединения и чтения старой базы для подмены не происходит.
3. При отсутствии новой базы проверяется `D:\EnglishNotesData\englishnotes.sqlite3`.
   Если файла/диска нет, выполняется обычное создание новой базы.
4. Если старая база есть, берётся блокировка прежней версии. Запущенное старое
   приложение блокирует перенос; закройте его и повторите запуск.
5. SQLite Backup API создаёт снимок во временном файле в новой папке. Подтверждённые
   записи из WAL входят в снимок. Проверяются quick_check, связи, версия и структура.
   Ожидание резервного копирования ограничено 10 секундами.
6. Проверенный файл публикуется атомарно, без замены существующего назначения:
   создание hard link в той же папке и удаление временного имени. Если другой процесс
   успел создать назначение, его база сохраняется. На файловой системе без поддержки
   hard links перенос завершится ошибкой, а исходная база останется нетронутой.
7. Исходник на D: сохраняется как резервная копия. После переноса работайте только
   в новой версии: изменения старой версии автоматически не объединяются с новой.

При отказе доступа, нехватке места, повреждённой/неподдерживаемой базе запуск
останавливается с сообщением. Пустая база вместо неудачно перенесённой не создаётся.
Данные остаются в исходнике. Если системе не удалось убрать временный файл
`migration-*.sqlite3`, его можно удалить при закрытом приложении; он не выбирается
как рабочая база и не заменяет исходник.

## Если уже есть две базы

Обе копии сохраняются, активна база в AppData. Не удаляйте её ради автоматического
переноса без отдельной резервной копии. Для ручного выбора базы закройте обе версии,
сохраните обе папки целиком, затем поместите выбранную базу вместе с её WAL/SHM
в пользовательскую папку. Автоматическое объединение баз не реализовано.

Новая версия не удаляет пользовательские файлы на D:, проект и виртуальное окружение.
EXE можно перемещать отдельно: его расположение не меняет путь к базе.

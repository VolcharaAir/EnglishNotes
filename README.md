# EnglishNotes

Windows Desktop-приложение для локальных заметок к занятиям английским.
Python 3.14+, PySide6, SQLite. Версия 0.2.0 сохраняет архитектуру и схему данных
первого этапа; добавлены переносимые пути, миграция и сборка Windows EXE.

## Возможности

Занятия и история, несколько заметок в каждом занятии, редактирование заголовков
и текста, подтверждение удаления, автосохранение, восстановление после закрытия.
Приложение работает без интернета. Облачной авторизации и синхронизации пока нет.

Автосохранение выполняется через 350 мс после изменения, при непрерывном вводе —
не позднее 2 секунд. Перед переключением/закрытием выполняется сохранение.
При ошибке текст остаётся в редакторе, переход и закрытие отменяются.
Принудительное завершение процесса может потерять ещё не записанные символы.

## Запуск готовой Windows-сборки

1. Откройте GitHub Releases и скачайте `EnglishNotes.exe` из опубликованного релиза.
   Если релиза ещё нет, владелец проекта может скачать артефакт
   `EnglishNotes-Windows-x64` из успешного запуска **Actions → Windows EXE**.
2. Для артефакта Actions извлеките EXE из ZIP. Запустите EXE двойным щелчком.
3. База создастся автоматически. Python, Git, настройка SQLite и интернет не нужны.

Поддерживаемая цель сборки: Windows 10/11 x64. EXE можно хранить в любой доступной
папке и перемещать между папками. Пользовательские данные остаются в профиле
пользователя. На другом компьютере будет собственная локальная база;
перенос EXE сам по себе не переносит заметки. Для переноса заметок закройте приложение
на обоих компьютерах и отдельно скопируйте папку данных, сохранив существующую копию.

Сборка пока не подписана сертификатом Windows. Подпись и репутация SmartScreen —
отдельная задача; данная версия не отключает проверки Windows.

## Хранение и обновление

| ОС | Папка данных |
|---|---|
| Windows | `%LOCALAPPDATA%\EnglishNotes` |
| macOS | `~/Library/Application Support/EnglishNotes` |
| Linux | `$XDG_DATA_HOME/EnglishNotes` или `~/.local/share/EnglishNotes` |

При отсутствии LOCALAPPDATA на Windows используется `~/AppData/Local/EnglishNotes`.
Относительные пути окружения отклоняются. В папке данных находятся
`englishnotes.sqlite3`, SQLite WAL/SHM, блокировка экземпляра и `temp/`.
Каталоги создаются автоматически. Путь не зависит от EXE, папки установки,
текущей директории или временной распаковки PyInstaller. Замена EXE не сбрасывает базу.
Для резервной копии закройте приложение и скопируйте папку данных целиком.

**Прежняя база на D:** при отсутствии новой базы выполняется безопасное копирование
из `D:\EnglishNotesData\englishnotes.sqlite3` через SQLite Backup API, включая WAL.
Исходник сохраняется. Уже существующая база в AppData не заменяется и не объединяется
со старой. Подробности: [docs/move-to-d.md](docs/move-to-d.md).
При ошибке переноса приложение показывает сообщение и не создаёт пустую базу взамен.
Отсутствие диска D: не мешает обычному первому запуску.

База не зашифрована. Ни базу, ни файлы пользователей нельзя добавлять в репозиторий
или в EXE. Учётные данные Supabase и секреты в приложении отсутствуют.

## Разработка

Windows, PowerShell, Python 3.14:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,build]"
.\.venv\Scripts\python.exe -m englishnotes
```

После подготовки окружения `start.cmd` запускает исходники через `pythonw` без консоли.
Ограничений на диск/папку исходников нет. Для macOS/Linux используйте `python3.14`,
`.venv/bin/python` и соответствующие команды. Воспроизводимая установка:
`uv sync --locked --extra dev --extra build` (зависимости зафиксированы в `uv.lock`).

## Тесты и сборка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests tools packaging
.\.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm EnglishNotes.spec
```

**Windows EXE собирается на Windows**, результат: `dist\EnglishNotes.exe`.
Самодостаточная onefile-сборка содержит Python, PySide6/Qt, SQLite и зависимости.
PyInstaller распаковывает runtime в системную TEMP-папку; база там не хранится.
Сборка на Linux не создаёт Windows EXE.

В CI: `windows-latest`, Python 3.14, locked-зависимости, lint, pytest, PyInstaller,
проверка запуска настоящего EXE и повторного запуска после его перемещения,
SHA-256 и Actions Artifact. Workflow запускается при push в main, pull request,
ручном запуске или теге `v*`. Только push версионного тега с успешной сборкой
публикует GitHub Release. Ошибки тестов/сборки/smoke блокируют релиз.
Команды локальной проверки и ручной чек-лист: [docs/testing.md](docs/testing.md).

## Структура

```text
src/englishnotes/
  app.py                 # QApplication, блокировки, запуск миграции, сборка зависимостей
  domain/                # Неизменяемые Lesson/Note, ошибки
  application/           # Сервис сценариев и протокол хранилища
  storage/               # SQLite, миграции схемы/путей, runtime-каталоги
  ui/                    # Главное окно, редактирование, автосохранение
  sync/                  # Только граница будущего адаптера
packaging/entrypoint.py   # Точка входа PyInstaller
EnglishNotes.spec        # Onefile GUI-сборка
.github/workflows/       # Windows build и релизы по тегам
tools/smoke_windows.py   # Проверка настоящего EXE на Windows
tests/                  # Хранилище, UI, пути, миграция и запуск
docs/                   # Архитектура, миграция и тестирование
```

Облачная синхронизация, совместные сессии и подключение по коду остаются за рамками
этого этапа. Архитектура: [docs/architecture.md](docs/architecture.md).

# Результаты проверки

Проверено 17 ноября 2026 года в Linux x86_64:

- Python **3.14.10**;
- PySide6 **6.12.0**;
- pytest **9.2.0**, pytest-qt **4.5.0**;
- Ruff **0.17.5**.

Команды в окружении разработки:

```text
.venv/bin/python -m pytest -q
64 passed in 2.86s

.venv/bin/ruff check src tests tools packaging
All checks passed!

.venv/bin/ruff format --check src tests tools packaging
28 files already formatted
```

## Что проверено

- Создание папки/SQLite-базы и схемы при первом запуске; повторное открытие.
- Полный цикл создания, редактирования, удаления и восстановления заметок.
- Разделение заметок по занятиям и стабильная сортировка.
- UUID, UTC-метки, ревизии и сохранение отметок удаления.
- Unicode, несколько строк, кавычки, SQL-подобный текст, пустые заголовки/заметки.
- Валидация без изменения записанных данных при ошибке.
- Отклонение изменений/удалений с устаревшей ревизией, в том числе с двух соединений.
- Откат обычной транзакции и неуспешной миграции.
- Отказ записи, занятая база, восстановление после снятия блокировки.
- Отказ от открытия неизвестной новой схемы и повреждённого файла без пересоздания.
- Обработка закрытого соединения и недоступной папки данных.
- Windows LocalAppData, macOS Application Support, Linux XDG и запасные пользовательские пути.
- Независимость пути базы от EXE/cwd/_MEIPASS, работа без диска D:.
- Миграция с WAL, сохранение исходника и tombstones, отказ от перезаписи существующей базы.
- Конкурентное создание назначения, ошибки доступа, повреждённая/будущая схема,
  нарушения связей, ограничение времени backup, блокировка запущенной старой версии.
- Полный запуск с миграцией и повторное открытие занятий, отказ создавать пустую базу
  при ошибке переноса.
- Реальные Qt-кнопки, редакторы, таймеры и горячая клавиша Ctrl+S.
- Автосохранение и ограничение задержки при непрерывном редактировании.
- Сохранение при переключении заметки/занятия и при закрытии окна.
- Восстановление данных в новом окне после закрытия и открытия базы.
- Подтверждение/отмена удаления и создание заметки после удаления последней.
- Сохранение текста в редакторе при ошибке, блокировка переходов и закрытия,
  повторное сохранение после восстановления записи, включая реальный отказ SQLite.
- Частичное сохранение: повторяется только неуспешная операция.
- Запуск полного bootstrap в отдельном процессе с автоматическим созданием базы
  во временной папке данных и освобождением блокировки после выхода.

Интерфейс дополнительно отрисован в режиме Qt offscreen и визуально проверен.
Демонстрационные записи для снимка создавались во временной базе и в проект не включены.

## Windows CI и проверка EXE

Workflow `.github/workflows/windows.yml` запускает тот же pytest на Windows runner,
затем PyInstaller и `tools/smoke_windows.py`. Последний действительно запускает
`dist/EnglishNotes.exe`, ждёт главного окна, закрывает его через WM_CLOSE,
создаёт проверочную запись в изолированном профиле и запускает перемещённый EXE.
После закрытия проверяет сохранность записи и целостность SQLite. Только после
успешных шагов публикуется артефакт `EnglishNotes-Windows-x64`.

Фактический результат конкретного Windows-запуска смотрите в Actions. Локальные
результаты Linux сами по себе не подтверждают запуск Windows EXE.

## Ручная проверка на Windows

1. Сохраните резервную копию существующих данных. Закройте обе версии.
2. На тестовом профиле без диска D: запустите готовый EXE двойным щелчком,
   убедитесь в отсутствии консоли и появлении `%LOCALAPPDATA%\EnglishNotes`.
3. Создайте занятие и заметку, введите кириллицу/английский текст, отредактируйте
   название. Сразу закройте окно, откройте снова и проверьте текст.
4. Добавьте вторую заметку, переключайте занятия, удалите заметку с подтверждением.
5. Закройте окно, переместите EXE в другую папку и повторите запуск: записи сохранены.
6. Обновите EXE, оставив пользовательскую папку данных: прежние записи доступны.
7. Отключите интернет и повторите создание/редактирование/закрытие/открытие.
8. Для миграции используйте отдельный тестовый профиль без целевой базы. Поместите
   тестовую базу версии 0.1.0 в `D:\EnglishNotesData`, запустите новый EXE и проверьте
   занятия и исходник. Повторите с двумя разными базами: AppData должна иметь приоритет.
9. Проверьте запрет записи/ошибку доступа: приложение должно показать сообщение,
   сохранив текст или исходную базу, а не создавать замену в другой папке.
10. На чистой Windows без установленного Python запустите EXE и повторите шаги 2–5.

CI запускается на машине с Python для сборки и проверок. Даже успешный smoke
не является ручной проверкой на чистой Windows без Python. Облачные сценарии,
совместные сессии и авторизация отсутствуют; они не тестируются на этом этапе.

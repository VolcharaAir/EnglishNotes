# Статус живого теста: PASS

17 ноября 2026 года. Полный запуск выполнен оператором на своём Windows-ПК
(Python 3.14.4) против его реального Supabase. Основание результата — присланный
полный консольный вывод: все проверки PASS, `Live Supabase security result: PASS`,
exit code 0. Из Codex этот живой запуск не выполнялся. Локальный JSON-отчёт
оператора не передавался; ключи, JWT, приглашение и ID тестовых записей здесь
не публикуются.

Перед запуском получен и проверен экспорт фактической схемы Supabase PostgreSQL
17.12: тела RPC/helper-ов, аргументы и колонки совпали с миграцией. После
исправления локального SUPABASE_URL read-only диагностика получила HTTP 200.
Сам живой тест также подтвердил соответствие применённых определений.

Дополнительно прошли:

- Три разных пользовательских UUID и три разных токена, выпущенных Auth.
- A создал настоящую контрольную заметку до проверок C: отсутствие доступа
  проверено на существующих данных, а не на пустом занятии.
- A и B изменили заметки друг друга; автор сохранился, revision увеличилась.
- B не получил SELECT к invitation_code_hash (HTTP 403).
- Состав остался ровно A/student и B/teacher. Teacher не означает владельца.

## Вывод и необходимые изменения

В проверенных сценариях обход RLS, подмена автора/владельца и изменение состава
участников не обнаружены. Это результат указанных сценариев, а не утверждение
об отсутствии любых уязвимостей проекта.

Политики, миграция, SQLite и Desktop-код не менялись. Исправлен локальный
SUPABASE_URL: нужен корневой HTTPS-origin проекта без /rest/v1/. Для разбора
первоначальной сетевой остановки добавлена безопасная read-only диагностика.
Service_role/secret key не использовались; claims/JWT вручную не подменялись.

Отдельно локально пройдены 106 pytest-тестов: прежние 64 и 42 offline-проверки
runner-а/диагностики. Они не подменяют приведённый выше живой результат.

## Граница проверки

Не проверялись живой Realtime-транспорт, интеграция с Desktop, массовые анонимные
регистрации/Sybil, глобальное/IP-ограничение запросов, восстановление потерянной
Auth-сессии и разрешение конфликтов синхронизации. Следующий этап не начинался.

Тестовые пользователи/занятие/заметки автоматически не удаляются: для этого
клиентских административных прав нет. Отчёт остаётся на ПК в
`work/supabase-live-report.json`. Не публикуйте .env или токены.
Порядок запуска и ручной очистки только тестовых данных:
[INTEGRATION_TESTS.md](INTEGRATION_TESTS.md).

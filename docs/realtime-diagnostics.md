# Исправление подключения Realtime

Живая проверка на Windows, присланная пользователем 17 ноября 2026 года:
восемь проверок Auth/RPC прошли; подключение A/B к private Realtime не подтвердилось.
Оставшиеся проверки не выполнялись. Это не полный PASS Desktop v2.

В клиентское сообщение `phx_join` добавлен обязательный `join_ref`:
[протокол Supabase](https://supabase.com/docs/guides/realtime/protocol).
Его отсутствие — конкретная ошибка клиента; установить причину отказа именно
в пользовательской сети без ответа WebSocket пока нельзя.

Добавлена диагностика `REALTIME_A/B/C`: фиксированные коды стадии/ошибки,
числа отправленных/принятых join и HTTP/close status. Сырые ответы, URL,
JWT, ключи и тексты исключений в диагностике не сохраняются. Логгер библиотеки
WebSocket отключён, поскольку он может передавать сырые ошибки handshake root-логгерам.
Запоздалые callbacks старого соединения не меняют состояние нового.

Живой тест печатает диагностику при отказе. Неподтверждённое соединение без явного
серверного отказа даёт BLOCKED, а отказ доступа разрешённым A/B — FAIL.
Автоматической подмены участников или открытия публичных каналов нет.

Локально проверяются wire frame настоящей библиотеки websocket-client на локальном
строгом WebSocket-сервере, приём ACK, отказы, DNS/TLS/timeout/HTTP категории,
отсутствие токенов в диагностике и обработка старых callbacks. Это локальные тесты,
а не проверка живого Supabase. После обновления два файла нужно проверить повторным
запуском `python supabase/tests/live_desktop.py --run` на Windows с прежним .env и
прежними work/desktop-live профилями. Тестовые личности сохранятся через vault.
